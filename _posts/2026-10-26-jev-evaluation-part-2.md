[전편](/posts/jev-integration-part-1/)에서는 자유로운 JSON 생성 대신 선택형 질문을 사용하는 Jev를 풋살 기록 서비스에 연결하는 설계를 다뤘다. 후편에서는 실제 API를 호출해 현재 연동 상태의 응답 속도와 기록 정확도를 비교한다.

이번 결과는 **모델과 현재 프롬프트·어댑터를 합친 시스템 비교**다. 모델 자체의 한국어 능력 순위나 전체 서비스의 응답 시간으로 일반화할 수 없다.

## 무엇을 어떻게 측정했는가

2026년 10월 26일 로컬 macOS 개발 환경에서 기존 서비스 해석기를 직접 실행했다. OpenAI는 요청 모델 `gpt-4.1-mini`, Jev는 `jev-1.14.0`을 사용했다. Jev의 실제 응답 모델 ID는 기록했지만, 기존 OpenAI 어댑터는 응답 모델 ID를 수집하지 않아 OpenAI의 실제 스냅샷은 확인하지 못했다.

실사용자 데이터 대신 합성 한국어 문장 30개를 준비하고 호출 전에 기대 결과를 고정했다. 선수는 별명 하나를 포함한 3명, 기존 기록은 우리 골과 상대 골 각 1개다. 단일 득점 4건, 어시스트 4건, 상대 득점 3건, 자책골 3건, 복수 득점 4건, 취소·정정 4건, 미등록·불명확한 선수 3건, 시간 표현 3건, 무관한 말·지시 삽입 2건을 포함했다.

각 문장을 모델별 3회 반복해 총 180번 호출했다. 문장과 반복 순서는 고정 시드로 섞고, 두 모델의 호출 순서는 번갈아 바꿨다. 동시성은 1, 재시도와 자동 대체 호출은 0이다. 별도 연결 확인 2회는 집계에서 제외했다. 별도 워밍업은 하지 않았으므로 본 실험의 첫 연결 비용은 측정에 포함된다.

측정 구간은 해석기 호출 직전부터 응답 해석 완료까지다. 요청 조립, 제공자와의 네트워크 왕복, 출력 변환은 포함하지만 Soniox 전사, 브라우저 업로드, 서버 인증·DB 처리, 미리보기 렌더링은 포함하지 않는다. **녹음 종료부터 화면 표시까지의 종단간 시험은 이번에 수행하지 않았다.**

## 결과

| 항목 | OpenAI | Jev |
|---|---:|---:|
| 호출 수 | 90 | 90 |
| 전체 정답 | 87/90 (96.7%) | 43/90 (47.8%) |
| 공통 범위 정답 | 84/84 (100%) | 43/84 (51.2%) |
| p50 | 1289.9 ms | 255.2 ms |
| p95 | 2178.1 ms | 425.9 ms |
| API 예외 | 0 | 0 |
| 어댑터 미지원 표시 | 0 | 3 |

이번 표본에서 Jev의 중앙값 지연은 OpenAI의 약 1/5.05, p95는 약 1/5.11이었다. 정답률은 현재 연동 상태에서 큰 차이가 났다.

정답 판정은 득점 팀·개수·선수 ID·어시스트 ID·분·취소 ID·미등록 이름이 기대값과 모두 일치하는지 검사했다. 골 목록의 순서는 무시하지만 중복 개수는 보존했다. 표현 설명, 이름 원문 필드, 경고 문장의 문구 자체는 채점하지 않았다. 따라서 모든 응답 필드를 평가한 점수는 아니다.

명단 밖 선수는 골을 남기고 선수 ID를 비워두며 미등록 이름을 돌려주는 것을 기대했다. 아예 골을 만들지 않고 보류한 결과도 이 엄격한 기준에서는 오답이다. 그런 사례는 허위 기록을 만드는 위험과 구분해서 읽어야 한다.

공통 범위는 자유 문자열의 미등록 이름 반환을 요구하는 2문장을 제외한 28문장이다. 각 3회이므로 분모는 84다. 시간·복수 골·취소·정정은 현재 연동이 지원하려는 기능이므로 실패했다고 분모에서 제외하지 않았다.

p95는 정렬된 90개 시간 중 86번째 값(nearest-rank)이다. 같은 30문장의 반복을 독립적인 새 문장 90개로 볼 수 없으며, 이 작은 표본에서 나온 p95는 운영 SLA가 아니다.

## 빠르게 응답해도 기록이 맞는 것은 아니다

| 입력 | 기대 | Jev에서 관찰한 결과 | 반복 실패 |
|---|---|---|---:|
| 민수 두 골 | 민수 골 2개 | 민수 골 1개 | 3/3 |
| 12분 민수 골 | 민수 골, 12분 | 민수 골, 시간 없음 | 3/3 |
| 방금 골 취소 | 마지막 골 취소 | 취소 목록 비어 있음 | 3/3 |
| 상대 수비수 자책골 | 우리 골 1개 | 우리 골과 상대 골 각각 1개 | 3/3 |
| 101번 골 득점자는 민수 말고 창명이야. 시간은 3분 그대로야 | 기존 골 취소 후 창명 3분 골 | 취소만 반환 | 3/3 |

OpenAI의 3회 불일치는 모두 “영희 골”이었다. 명단 밖 이름 “영희”는 반환했지만 골 목록을 비웠다. 이 결과는 미등록 선수를 임의로 연결한 오류와 성격이 다르다. Jev는 미등록 이름을 원문으로 반환하지 못해 관련 2문장 모두 엄격한 기준에서 불일치했다.


형식이 올바른 HTTP 응답과 사용자가 기대한 기록은 다르다. 예를 들어 골 개수를 줄이거나 명시된 시간을 누락한 결과도 API 호출 자체는 성공할 수 있다. 미지원 표시만으로 의미상 오답을 모두 찾을 수 없으므로, 별도 정답 평가가 필요하다.

이번 평가에서는 결과를 본 뒤 질문이나 확률 임계값을 조정하지 않았다. 따라서 Jev의 낮은 점수를 모델만의 한계로 단정할 수 없다. 선택형 질문 설계, 후보 선택과 보류 임계값, 출력 조립 로직을 함께 조사해야 한다. 개선 후에는 같은 평가 문장에 과적합하지 않도록 별도의 검증 세트를 추가해야 한다.

## 토큰 단가와 요청 비용은 다르다

| 90회 합계 | OpenAI | Jev |
|---|---:|---:|
| 입력 토큰 | 162,084 | 1,271,883 |
| 출력 토큰 | 4,632 | 597,082 |
| 일반 단가 기준 추정 비용 | $0.072245 | $0.053419 |
| 엄격한 정답 1건당 추정 비용 | $0.000830 | $0.001242 |

일반 단가를 적용하면 Jev의 전체 비용은 약 26% 낮지만, 엄격한 정답당 비용은 더 높았다. Jev 입력 토큰은 약 7.85배였다. OpenAI의 캐시 적용 여부에 따라 실제 비용 순위는 달라질 수 있어 실제 청구 비용 절감이라고 단정하지 않는다.

가격 기준은 2026년 10월 26일 확인한 공식 문서다. [OpenAI](https://developers.openai.com/api/docs/models/gpt-4.1-mini)는 입력 100만 토큰당 $0.40, 캐시 입력 $0.10, 출력 $1.60이다. [TypeSafe](https://docs.typesafe.ai/models)는 입력 100만 토큰당 $0.042이며 출력은 무료다.

이번 OpenAI 어댑터는 캐시 토큰을 별도로 수집하지 않는다. 표의 OpenAI 비용은 입력 전체에 일반 단가를 적용한 추정값으로, 캐시 할인이 적용된 실제 청구액과 다를 수 있다. Jev 역시 응답 usage와 공개 단가를 곱했을 뿐 결제 내역을 대조하지 않았다. 무료 크레딧, 세금, STT 비용은 반영하지 않았다.

계산은 다음처럼 단순하지만 분모를 함께 봐야 한다.

```python
nominal_cost = input_tokens * input_rate + output_tokens * output_rate
cost_per_correct_result = nominal_cost / correct_results
```

선택형 질문과 선택지를 많이 보내면 토큰 단가가 낮아도 요청당 입력량이 커진다. 출력 토큰 수 역시 두 API의 생성 방식이 달라 처리 속도의 직접 비교 지표로 쓰지 않았다.

## 지금의 선택과 다음 실험

현재 연동 그대로 기본 모델을 전면 교체하기보다는 OpenAI를 유지하면서 Jev를 관리자 비교 대상으로 두는 판단이 적절하다. Jev의 지연 감소는 확인했지만, 실제 저장할 기록의 정확도를 먼저 개선해야 한다.

다음 실험은 실패한 시간·개수·취소 표현의 원인을 질문과 결과 변환 단계에서 구분하는 것이다. 이후 긴 선수 명단, 동명이인, 명단 순서 변경, 더 많은 기존 골, 표현이 다른 미사용 평가 세트로 다시 검증할 필요가 있다. 마지막으로 같은 녹음 파일을 사용해 STT와 브라우저 미리보기까지 측정해야 실제 사용자 경험의 개선 폭을 말할 수 있다.

이번 결과의 범위는 한국어 합성 문장 30개, 선수 3명, 기존 골 2개, 단일 실행 위치와 시간대다. 전면적인 품질 보증이나 모든 스포츠에 대한 결론은 아니다.
